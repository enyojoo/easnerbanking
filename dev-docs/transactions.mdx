A transaction is a row on `GET /v1/transactions`. Receive writes vault credits (`deposit`, `chain`, `onramp`). Send writes vault debits (`transfer`). Checkout collects also appear here when you used a merchant secret key — those are **your** business balance, not a customer vault.

In Console, these rows are **Payments**. Open a `txn_` for type, source, destination, and the related `tr_` / `cs_`.

<Note>
  **Scope:** `accounts.read`
</Note>

## Object

| Field | Type | Notes |
|---|---|---|
| `id` | string | `txn_…` |
| `type` | string | `transfer`, `deposit`, `onramp`, `chain`, `easetag`, `checkout` |
| `amount` | integer | Cents, always positive |
| `currency` | string | |
| `direction` | string | `in` or `out` |
| `status` | string | `completed`, `pending`, `failed` |
| `account` | string \| null | `acct_…` for issued-account activity |
| `customer` | string \| null | `cus_…` |
| `transfer` | string \| null | `tr_…` |
| `checkout_session` | string \| null | `cs_…` |
| `description` | string \| null | |
| `livemode` | boolean | |
| `created` | ISO-8601 | |

## Types

| `type` | Product | Meaning |
|---|---|---|
| `deposit` | Banking | Bank credit to a customer `acct_` |
| `onramp` | Banking | Card onramp credit to a customer `acct_` |
| `chain` | Banking | Chain credit to a customer `acct_` |
| `easetag` | Banking | In-network credit to a customer `acct_` |
| `transfer` | Banking | Send from a customer `acct_` |
| `checkout` | Checkout | Collect onto **your** business balance |

`checkout` is not Receive. It does not credit a customer `acct_`. Banking mode in the app also shows that collect.

## List

```bash
curl https://api.easner.com/v1/transactions \
  -H "Authorization: Bearer $EASNER_SECRET_KEY"
```

```json
{ "data": [ /* Transaction */ ] }
```

Newest first. Up to 100. There is no next page. Filtered by the key’s livemode.

## Retrieve

`GET /v1/transactions/:id` → Transaction. `404` if missing or the other mode.

## Events

| Event | When |
|---|---|
| `transaction.created` | A row was written. Webhook `data` is **narrower** than this GET object — see [Webhooks](/webhooks) |
| `account.updated` | The account totals changed |
| `payment.available` | A Checkout collect became usable |

## Expected

- Reconcile your product against this list.
- `direction: "in"` with `deposit` / `onramp` / `chain` / `easetag` is Receive on a customer account.
- `direction: "in"` with `checkout` is a collect onto your business balance.
- `direction: "out"` is a transfer.
