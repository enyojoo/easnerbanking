A transfer sends from a customer **vault** to a [payment method](/send). Prefer quote-then-transfer so the amounts are locked.

<Note>
  **Scope:** `POST` needs `transfers.write`. `GET` needs `accounts.read`.
</Note>

Send restrictions apply. A restricted business cannot create transfers.

## Create from a quote

Always send `Idempotency-Key`.

```bash
curl https://api.easner.com/v1/transfers \
  -H "Authorization: Bearer $EASNER_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"quote":"qt_…"}'
```

The transfer uses the quote’s send amount, source, and destination. A replay with the same idempotency key returns the same transfer.

`201`. On success the customer account is debited and a transaction is written.

## Create without a quote

You may pass `source`, `destination`, `amount`, and `currency` instead of `quote`. Prefer a quote when the destination can change receive amounts.

## Retrieve and list

`GET /v1/transfers/:id` → Transfer. `404` if missing.

`GET /v1/transfers` → `{ "data": [ Transfer, … ] }` newest first, up to 100.

## Status

| Status | Expected |
|---|---|
| `created` | Accepted. Webhook `transfer.created` |
| `completed` | Account debited. Webhook `transfer.completed` |
| `failed` | No debit, or debit rolled back. Webhook `transfer.failed` |

Test completes without moving live rails. Live wallet (Solana USDC/EURC), Easetag, bank, and mobile money leave the customer vault. Live bank and mobile money require `approved` verification and a corridor from `GET /v1/payment_methods`.

## Events

| Event | `data` |
|---|---|
| `transfer.created` | The transfer |
| `transfer.completed` | The transfer |
| `transfer.failed` | Transfer plus `error` |
| `transaction.created` | The ledger row |
| `account.updated` | New available balance |

<Warning>
  Fulfil on `transfer.completed`, not on the HTTP `201` alone, if your product can retry.
</Warning>
