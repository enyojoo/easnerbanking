Easner POSTs signed events to your URLs. Create as many endpoints as you need per mode (test and live may differ). Tick which events you want in Settings → Webhooks. Unticked events are not sent. Disable is reversible — Enable puts the endpoint back.

Headers on every delivery:

| Header | Value |
|---|---|
| `content-type` | `application/json` |
| `easner-event` | The event name, e.g. `transfer.completed` |
| `easner-signature` | `t=<unix>,v1=<hex>` |

Body:

```json
{
  "type": "transfer.completed",
  "created": 1758336000,
  "data": {
    "id": "tr_…",
    "amount": 4900,
    "currency": "USD",
    "status": "completed",
    "livemode": false
  }
}
```

Return `2xx` quickly. Do the work after you ACK, or keep the handler short. Anything else is a failure and will retry.

## Verify `easner-signature`

HMAC-SHA256 of the Unix timestamp, a period, and the raw body. Compare with `v1` using a constant-time compare. Reject if the timestamp is older than 5 minutes.

```js
import { createHmac, timingSafeEqual } from "node:crypto";

export function verifyWebhook(rawBody, signatureHeader, secret) {
  const parts = Object.fromEntries(
    String(signatureHeader || "")
      .split(",")
      .map((part) => part.trim().split("=", 2)),
  );
  const timestamp = Number(parts.t);
  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const got = String(parts.v1 || "");
  if (got.length !== expected.length) return false;
  if (Math.abs(Date.now() / 1000 - timestamp) > 300) return false;
  return timingSafeEqual(Buffer.from(expected), Buffer.from(got));
}
```

Use the **raw** body. Re-serializing JSON will fail the signature.

## Catalog

Tick these in Settings → Webhooks. Default ticks are Banking: `customer.updated`, `account.updated`, `transfer.completed`, `transaction.created`. Add Checkout events when you collect on a site.

### Checkout

**`checkout.completed`** — Payment succeeded. Fulfil the order. Credits **your** business balance.

```json
{
  "type": "checkout.completed",
  "created": 1758336000,
  "data": {
    "checkout_session_id": "cs_…",
    "mode": "payment",
    "amount_cents": 4900,
    "currency": "USD",
    "customer_email": "ada@example.com",
    "subscription_id": null,
    "metadata": { "order_id": "ord_123" },
    "paid_at": "2026-09-20T00:00:00.000Z",
    "livemode": false
  }
}
```

**`checkout.async_succeeded`** — A delayed method (bank debit) cleared.

**`checkout.failed`** — Abandoned or failed. Do not fulfil.

**`payment.available`** — Funds are usable on your business balance.

```json
{
  "type": "payment.available",
  "created": 1758336000,
  "data": { "amount_cents": 4750, "currency": "USD", "available_at": "2026-09-20T00:00:00.000Z" }
}
```

**`subscription.updated`** / **`subscription.canceled`**

```json
{
  "type": "subscription.updated",
  "created": 1758336000,
  "data": { "subscription_id": "sub_…", "status": "active", "metadata": { "user_id": "123", "plan": "pro" } }
}
```

### Banking

**`account.updated`** — Available or pending changed. Default tick.

```json
{
  "type": "account.updated",
  "created": 1758336000,
  "data": {
    "id": "acct_…",
    "currency": "USD",
    "available": 4900,
    "pending": 0,
    "customer": "cus_…",
    "livemode": false
  }
}
```

**`customer.updated`** — Record changed, including `verification_status`. Default tick. `customer.created` is the same `data` shape; tick it if you need create.

```json
{
  "type": "customer.updated",
  "created": 1758336000,
  "data": {
    "id": "cus_…",
    "email": "ada@example.com",
    "name": "Ada",
    "external_id": "user_42",
    "easetag": "ada",
    "status": "active",
    "verification_status": "approved",
    "livemode": false,
    "created": "2026-09-20T00:00:00.000Z"
  }
}
```

**`transfer.completed`** — Vault sent. Default tick. `data` is the transfer **without** `client_secret`. Also tick `transfer.created` / `transfer.failed` if you handle those.

```json
{
  "type": "transfer.completed",
  "created": 1758336000,
  "data": {
    "id": "tr_…",
    "quote": "qt_…",
    "source": "acct_…",
    "destination": "dest_…",
    "amount": 4900,
    "currency": "USD",
    "status": "completed",
    "livemode": false,
    "created": "2026-09-20T00:00:00.000Z",
    "expires_at": "2026-09-20T00:15:00.000Z",
    "next_action": null
  }
}
```

**`transfer.failed`** — optional tick. Same transfer fields plus `error`:

```json
{
  "type": "transfer.failed",
  "created": 1758336000,
  "data": {
    "id": "tr_…",
    "quote": "qt_…",
    "source": "acct_…",
    "destination": "dest_…",
    "amount": 4900,
    "currency": "USD",
    "status": "failed",
    "livemode": false,
    "created": "2026-09-20T00:00:00.000Z",
    "expires_at": "2026-09-20T00:15:00.000Z",
    "next_action": null,
    "error": "Transfer expired"
  }
}
```

**`transaction.created`** — A ledger row was written. Default tick. This payload is **narrower than** `GET /v1/transactions/:id`. Receive `type` is `deposit`, `onramp`, `chain`, or `easetag`.

```json
{
  "type": "transaction.created",
  "created": 1758336000,
  "data": {
    "id": "txn_…",
    "type": "deposit",
    "amount": 4900,
    "currency": "USD",
    "direction": "in",
    "status": "completed",
    "livemode": false
  }
}
```

## Retries

Failed deliveries retry at 1 minute, 5 minutes, 30 minutes, 2 hours, then 24 hours. After five attempts the delivery is `failed`. Redeliver from Settings → Webhooks.

Deliveries are listed there. Use Send test to confirm the URL is reachable; that is not a real payment. Events in Console is a log of every event, not this catalog.

## Expected handler

<Steps>
  <Step title="Read the raw body">
    Do not re-serialize JSON before verifying.
  </Step>
  <Step title="Verify `easner-signature`">
    HMAC-SHA256 of timestamp plus raw body. Reject timestamps older than 5 minutes.
  </Step>
  <Step title="Switch on `type`">
    Branch on the event name, not the message text.
  </Step>
  <Step title="Fulfil idempotently">
    Use `checkout_session_id`, `id` on the transfer, or your `metadata`.
  </Step>
  <Step title="Return `200`">
    ACK quickly. Do heavier work after.
  </Step>
</Steps>
