Send from a customer account in test. Nothing hits live rails.

You need:

- Dev Platform enabled on the business
- A test secret key from Console → Keys (`easner_sk_test_…`)
- `EASNER_SECRET_KEY` set in your shell

```bash
export EASNER_SECRET_KEY=easner_sk_test_…
```

<Steps>
  <Step title="Create a customer">
    A customer is your end user. Creating one opens their USD vault (USDC) and issues `acct_`.

    ```bash
    curl https://api.easner.com/v1/customers \
      -H "Authorization: Bearer $EASNER_SECRET_KEY" \
      -H "Content-Type: application/json" \
      -d '{"email":"ada@example.com","name":"Ada","external_id":"user_42"}'
    ```

    Save `id` (`cus_…`) and the issued `accounts[0].id` (`acct_…`).
  </Step>
  <Step title="Add a destination">
    A payment method. Easetag is the simplest test destination (in-network). For bank, mobile money, or wallet, see [Send](/send).

    ```bash
    curl https://api.easner.com/v1/destinations \
      -H "Authorization: Bearer $EASNER_SECRET_KEY" \
      -H "Content-Type: application/json" \
      -d '{"type":"easetag","customer":"cus_…","details":{"easetag":"ada"}}'
    ```

    Save `id` (`dest_…`).
  </Step>
  <Step title="Quote">
    Lock send and receive. `source` is required. Amounts are cents. Quotes expire in 15 minutes.

    ```bash
    curl https://api.easner.com/v1/quotes \
      -H "Authorization: Bearer $EASNER_SECRET_KEY" \
      -H "Content-Type: application/json" \
      -d '{"amount":4900,"currency":"usd","source":"acct_…","destination":"dest_…"}'
    ```

    Save `id` (`qt_…`). In test, send and receive are 1:1 unless a live wallet destination is priced.
  </Step>
  <Step title="Transfer">
    Execute the quote. Always send `Idempotency-Key` so a retry does not send twice.

    ```bash
    curl https://api.easner.com/v1/transfers \
      -H "Authorization: Bearer $EASNER_SECRET_KEY" \
      -H "Content-Type: application/json" \
      -H "Idempotency-Key: $(uuidgen)" \
      -d '{"quote":"qt_…"}'
    ```

    Expected: `status` moves to `completed` (test) or stays `created` then completes. The customer account is debited. A `txn_` row is written.

    Listen for `transfer.completed` and `transaction.created` on your webhook.
  </Step>
  <Step title="Read activity">
    ```bash
    curl https://api.easner.com/v1/transactions \
      -H "Authorization: Bearer $EASNER_SECRET_KEY"
    ```
  </Step>
</Steps>

A new test account starts at `available: 0`. Fund it with [Receive](/receive) before a live-sized send, or keep the first transfer in test against a funded account.

## Collect instead of send

To take a payment on your website, go to [Checkout](/checkout). That credits **your** business balance, not this customer `acct_`.
