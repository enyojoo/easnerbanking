Send from a customer account in test. Nothing hits live rails. Every public method is on [v1 reference](/reference).

## Open Console

Stay in **Test**. Settings is API keys, webhooks, logs, and Workbench.

<Steps>
  <Step title="Mint a test key">
    Settings → API keys. The list is the **current** Test or Live mode only. Create as many keys as you need. Copy the secret once into your server env.

    ```bash
    export EASNER_SECRET_KEY=easner_sk_test_…
    ```
  </Step>
  <Step title="Add a webhook URL">
    Settings → Webhooks. Create as many URLs as you need. Default ticks are Banking: `customer.updated`, `account.updated`, `transfer.completed`, `transaction.created`. Add Checkout events if you take payments on a site.
  </Step>
</Steps>

You need Dev Platform enabled on the business and that test secret.

## First send

<Steps>
  <Step title="Create a customer">
    A customer is your end user. Creating one opens their USD vault (USDC) and issues `acct_`.

    ```bash
    curl https://api.easner.com/v1/customers \
      -H "Authorization: Bearer $EASNER_SECRET_KEY" \
      -H "Content-Type: application/json" \
      -d '{"email":"ada@example.com","name":"Ada","external_id":"user_42"}'
    ```

    Save `id` (`cus_…`) and the issued `accounts[0].id` (`acct_…`).
  </Step>
  <Step title="Fund the test vault">
    A new `acct_` is `available: 0`. In Console, open Accounts → **Simulate test deposit** (session API, **not** `/v1`, test only). Or `POST /v1/accounts/acct_…/onramp_sessions` and complete the hosted test page. Wait for `account.updated`.
  </Step>
  <Step title="Add a destination">
    A payment method. Easetag is the simplest test destination (in-network). For bank, mobile money, or wallet, see [Send](/send).

    ```bash
    curl https://api.easner.com/v1/destinations \
      -H "Authorization: Bearer $EASNER_SECRET_KEY" \
      -H "Content-Type: application/json" \
      -d '{"type":"easetag","customer":"cus_…","details":{"easetag":"ada"}}'
    ```

    Save `id` (`dest_…`).
  </Step>
  <Step title="Quote">
    Lock send and receive. `source` is required. Amounts are cents. Quotes expire in 15 minutes.

    ```bash
    curl https://api.easner.com/v1/quotes \
      -H "Authorization: Bearer $EASNER_SECRET_KEY" \
      -H "Content-Type: application/json" \
      -d '{"amount":4900,"currency":"usd","source":"acct_…","destination":"dest_…"}'
    ```

    Save `id` (`qt_…`). In test, send and receive are 1:1 unless a live wallet destination is priced.
  </Step>
  <Step title="Transfer">
    Create the send. Always send `Idempotency-Key`.

    ```bash
    curl https://api.easner.com/v1/transfers \
      -H "Authorization: Bearer $EASNER_SECRET_KEY" \
      -H "Content-Type: application/json" \
      -H "Idempotency-Key: $(uuidgen)" \
      -d '{"quote":"qt_…"}'
    ```

    Expected: `status` is `requires_action`. Save `id` and `client_secret`.
  </Step>
  <Step title="Confirm">
    In your app the customer reviews, then you confirm with the `client_secret` — not the secret key. Or open `next_action.url`. See [Transfers](/transfers#confirm).

    ```bash
    curl https://api.easner.com/v1/transfers/tr_…/confirm \
      -H "Content-Type: application/json" \
      -d '{"client_secret":"easner_ta_test_…"}'
    ```

    Expected: `status` is `completed`. The test vault is debited. A `txn_` row is written.

    Listen for `transfer.completed` and `transaction.created` on your webhook.
  </Step>
  <Step title="Read activity">
    ```bash
    curl https://api.easner.com/v1/transactions \
      -H "Authorization: Bearer $EASNER_SECRET_KEY"
    ```
  </Step>
</Steps>

A new test account starts at `available: 0`. Fund it before the first send (step above). For live-sized sends, use [Receive](/receive).

## Take a payment on your website

To accept online payments, go to [Checkout](/checkout). Those funds land on **your** business balance, not this customer `acct_`.
