Livemode is the key prefix. There is no `livemode` body flag.

| | Test (`easner_sk_test_`) | Live (`easner_sk_live_`) |
|---|---|---|
| Objects | Isolated test objects | Isolated live objects |
| Verification | Approves immediately. No hosted form | Hosted link. Live bank details and onramp need `approved` |
| Virtual account | Sandbox numbers. No real bank | Named ACH/SEPA after approval. Fiat converts into the vault |
| Wallet address | Token account without KYC | Require `approved`. USDC/EURC into the vault |
| Onramp | Hosted page completes and credits the vault | Hosted card onramp after approval, onto the vault |
| Quote | Completes. Send/receive 1:1 | May price wallet destinations |
| Transfer | Completes. Debits the **test** vault | Wallet, Easetag, bank, and mobile money leave the live vault |
| Checkout | Test card `4242…`. Nothing charged | Real collect onto your business balance |
| Webhooks | Your test URL | Your live URL |

Test never moves live money. Live never writes test objects.

## What you must do before live

<Steps>
  <Step title="Mint a test key">
    Console: add a test webhook. Tick the events you handle.
  </Step>
  <Step title="Run the quickstart">
    [Quickstart](/quickstart) a customer → destination → quote → transfer. Confirm `transfer.completed` on the test URL.
  </Step>
  <Step title="Receive in test">
    [Receive](/receive): start verification, fetch sandbox bank details, complete a test onramp. Confirm `account.updated` and `transaction.created`.
  </Step>
  <Step title="Pay with the test card">
    Checkout: register the website, create a test session, pay with `4242`, confirm `checkout.completed`.
  </Step>
  <Step title="Check Console Logs">
    You should see the `v1` calls. Errors should be gone.
  </Step>
  <Step title="Mint a live key">
    Set a live webhook URL. Tick the same events.
  </Step>
</Steps>

## What you should not do

<Warning>
  Do not reuse a test key in production. Do not fulfil from the browser `onSuccess` without the webhook. Do not treat Checkout as Receive — a collect does not credit a customer `acct_`.
</Warning>

## Restriction

If the business is restricted for send or deposit, matching writes fail with `permission`.
